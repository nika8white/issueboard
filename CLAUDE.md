# CLAUDE.md

## What this is

IssueBoard: a to-do app used to learn the full path from laptop to production (Docker → Compose → Kubernetes → GKE, CI/CD with approvals). The owner works through a course step by step; course snippets often contain placeholders like `PROJECT_ID` or `your-github-user` that must be replaced with the real values below.

| Folder | Stack |
|---|---|
| `api/` | Express 5 + `pg`, TypeScript (ESM, `.js` import suffixes), Vitest + Supertest |
| `web/` | React 19 + Vite 8, Tailwind v4, shadcn/ui (`radix-nova` style, `@/` alias → `src/`) |
| `agent/` | NestJS 12 service (new; not yet in Compose, CI, or k8s). Read `agent/AGENTS.md` before working there |
| `k8s/` | Kustomize: `base/` + overlays `local/` (kind) and `gke/` |
| `.github/workflows/` | `ci.yml` (PRs + main), `deploy.yml` (main → GKE) |

Use Node 24 (`.nvmrc`). npm 10 (Node 22) crashes with `Cannot read properties of null (reading 'edgesOut')` on NestJS 12 peer deps.

## Commands

```sh
# API (cd api)
npm run dev                      # tsx watch, needs Postgres on localhost:5432
npm run lint                     # tsc --noEmit
npm test                         # unit tests; DB integration tests are skipped without DB_HOST
npx vitest run src/server.test.ts -t "answers /healthz"   # single test
npm run build                    # tsc → dist/

# Web (cd web)
npm run dev                      # Vite; proxies /api to localhost:3000
npm run lint && npm run build
npx shadcn@latest add <component> -y      # adds to src/components/ui/

# Whole stack locally (repo root)
docker compose up -d --build     # db, api (dev target), web :8080, adminer :8082
docker compose watch             # syncs api/src, rebuilds web on change
kubectl kustomize k8s/overlays/gke > /dev/null   # what CI's "manifests" job checks
```

Integration tests (`*.int.test.ts`) run against a throwaway Postgres:

```sh
docker run -d --rm --name ib-test-pg -e POSTGRES_USER=issueboard -e POSTGRES_PASSWORD=issueboard \
  -e POSTGRES_DB=issueboard -p 55432:5432 postgres:17-alpine
DB_HOST=localhost DB_PORT=55432 npm test     # in api/
docker stop ib-test-pg
```

## API architecture (`api/src/server.ts`)

- One `issues` table backs the to-do UI: `severity` = priority (`low|medium|high`), `status` `closed` = done, `due_date` is `DATE` returned as a `YYYY-MM-DD` string (custom pg type parser, avoids timezone shifts). The URL and table keep the name `issues`.
- Schema changes go in `migrate()`, which runs on every start: keep them additive and idempotent (`ADD COLUMN IF NOT EXISTS`), because production has existing rows.
- `validate()` whitelists fields; `PATCH` builds `SET` from that whitelist only. `DELETE /api/issues` requires `?status=closed`.
- `/healthz` = liveness (never touches DB), `/readyz` = readiness (DB query), `/api/version` = `APP_VERSION` (the commit SHA in production; the deploy smoke test checks it).
- Logging: `log(severity, message, fields)` from `log.ts` writes one JSON line for Cloud Logging. Don't use `console.*`.
- The Express error handler (4 args) must stay after all routes. Express 5 forwards rejected async handlers to it.
- DB password: `DB_PASSWORD_FILE` (mounted secret, trimmed) wins over `DB_PASSWORD`, then the local default.

## Web architecture

`src/lib/api.ts` is the only place that calls the API. `App.tsx` holds state and filter/sort logic; `components/todo-item.tsx` does view + inline edit. `components/ui/*` is generated by shadcn: don't hand-edit (ESLint's react-refresh rule is off there for that reason). In production, nginx (`web/nginx.conf`) serves the build and proxies `/api/` to the `api` service, so the same image works in Compose and Kubernetes.

`env.sh` (gitignored) exports `PROJECT_ID`, `REGION`, `CLUSTER`, `AR`; run `source env.sh` before manual `gcloud`/`docker push` commands.

How the k8s pieces fit:
- `base/` has the Deployments, Services, the API HPA (2–5 pods, so no `replicas:` in the Deployment) and a PDB.
- `overlays/gke/api-cloudsql.yaml` is a strategic-merge **patch**: it adds the proxy sidecar, secret volume, and service account. Containers merge **by name**. The IDE's "Missing property containers" warning on it is expected.
- `api-networkpolicy.yaml` only admits `web` pods and Google LB ranges (`130.211.0.0/22`, `35.191.0.0/16`) to port 3000; in-cluster debugging pods can't reach the API directly. Use `kubectl exec` into an api pod instead.
- The Gateway forwards `/api` paths unchanged, so only `/api/*` routes are reachable from outside (`/readyz` is not).
- Two kube contexts exist: `kind-issueboard` (local) and `gke_issueboard-25603_europe-west3_issueboard`. Check `kubectl config current-context` before applying anything.

## Delivery workflow

- `main` is protected by the `protect-main` ruleset: changes go through a PR, and the branch must be up to date with `main` (`gh pr update-branch <n>`). Don't merge with `--admin`.
- CI jobs: `api`, `web`, `manifests`, `changes`, `images`. `images` runs only when `api/**` or `web/**` changed (`dorny/paths-filter`). It builds both images and runs Trivy, which fails on fixable CRITICAL CVEs, usually from base images (e.g. remove npm from the API runtime stage, `apk upgrade` in the nginx stage).
- Every push to `main` triggers `deploy.yml`: build/push `:<sha>` → wait for approval on the `production` environment → `kustomize edit set image` + `kubectl apply -k k8s/overlays/gke` → rollout status (5 min) → smoke test that `/api/version` returns the SHA through the Gateway.
- **Only the owner approves production deployments** (Actions → run → Review deployments). Don't approve or reject deployment runs; ask. Deploys run one at a time (`concurrency: deploy-production`), so an older run waiting for approval blocks newer ones.
